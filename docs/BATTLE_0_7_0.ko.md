# 0.7.0 첫 전투와 전투 저장

시작 화면 → 첫 장면(필드 1) → 동굴 진입(필드 2) → 첫 전투 6 → 전투 후 장면(필드 3)을 연결했다. 다음 전투 219는 이번 범위에 포함하지 않는다. 이전 수동 검증판과 달리 적이 자동으로 이동·공격하며, 원본 출구/전멸 조건으로 전투가 끝난다.

## 설치와 조작

`g3nx-scenario-0.7.0.zip`의 `switch/g3nx` 폴더 전체를 SD 카드에 복사한다. NRO만 교체하면 새 자산 검증을 통과하지 못한다. 기존 hbmenu에서 실행한다.

- 방향키/왼쪽 스틱: 전투 목적지·목표 선택. A: 이동/공격, 대사 진행, 승리 후 다음 장면.
- R: 현재 행동 종료. L: 현재 유닛으로 커서 이동.
- X: 모든 장면에서 저장. 공격·이동·전투 대사 중에도 가능하다. 메뉴의 Load Game으로 복원한다.
- ZR: 전투 처음부터 재시작. ZL: 기존 이동 검증 모드로 전환하며 초기화한다.
- Y: 음소거. B: 메뉴. PLUS: 종료.

X의 기존 전투 초기화 기능은 ZR로 옮겼다. 패배 후에는 ZR로 재시작하거나 B로 돌아가 저장을 불러온다. 잘못 저장한 직후 다른 자동 저장이 생기는 방식은 아니다.

## 원본 근거와 변경

BTL 유닛 레코드의 바이트 8은 **방향**이다. 이전 0.5/0.6의 팀 해석을 정정했다. 실제 팀은 바이트 12의 16비트 값으로 아군 4, 적 0이다 (`1002D27B/1002D294`). 팀 3과 4는 서로 우호적이다. 같은 시각에서는 팀 0이 4보다 먼저 행동한다.

BTL 6의 원본 이벤트 9개를 실행한다. 인트로 대사 0/1/2, 아군 4 전멸 시 패배, 적 0 전멸 시 승리, 아군이 x=6..16/y=0..3에 진입하면 출구 대사 3/4 후 승리한다. 아지다하카 근처 지역 대사 8/9와 살라딘 접촉 시 대사 10/11/12 및 해당 아지다하카의 팀 3 전환도 복원했다. 접촉은 같은 행 또는 열이고 `40*(|dx|+|dy|)+20*|높이차|<=80`이다. 조건 200/301/302 및 명령 100/200/509/706의 확인 주소는 `1001D304`, `1001D990`, `1001DA00`, `100210B0`이다.

적의 AI.DAT 프로필 1을 확인해 구현했다 (`10026140`, `100261B0`, `10026320`, `10028C00`, `1002B180`, `1003F950`). 이동 후 공격, 피해량 기반 목표 우선순위, 탐색 반경 100, HP 20% 이하의 후퇴 분기, 원본 목표 포인터 정렬 특성을 포함한다. 피해량 예측도 원본 난수를 소비한다. 적과 같은 높이의 바로 옆 칸에는 멈출 수 없는 별도 제약도 적용했다 (`1008A020/10089C60`).

정지·보행·공격·피격은 OBS 원본 프레임/방향을 사용한다. **DAT 타격 횟수만큼 직접 피해를 반복하던 방식을 제거**하고 OBS 명령 5의 실제 시각에 주무기/보조무기 타격을 적용한다. 공격 1은 원본 분기의 난수로 기본 동작 6/9를 선택하며, 공격 352/297은 기본 동작 6이다. 첫 전투의 보조무기는 주무기와 같은 다마스커스인 경우만 허용한다. 반격/역습 능력 78/79는 첫 배치에서 모두 0이며 생성 시 검사한다. 임의의 상태·반격 시스템을 추가한 것은 아니다.

OBS 명령 2의 효과 231/291/669/880, 피격 효과 796과 명령 1의 효과음 11종을 재생한다. 효과의 부모·상대 좌표·지속 시간도 보존한다. 일반 생존 피격의 효과 선택은 원본처럼 난수를 한 번 소비하고, 전투불능 피격은 고정 효과 0을 사용한다 (`1003DECF/1003DF8B`, `100986F3`, `10099EA0`). 음향은 기존 PCM BGM에 최대 4개 효과음을 포화 덧셈으로 혼합한다. 전투 BGM은 BTL 헤더[8]의 6이다 (`1002D918..1002D935`). 필드 3의 곡은 3이며 기존 35/42도 유지한다.

필드 3은 원본 배경 139, 대사 16개, FLD 이벤트를 독립 실행기로 재생한다. 필드 1의 실행기와 같은 코드를 별도 데이터에 컴파일한다.

## 저장과 검증

`g3nx-session-0.bin`/`g3nx-session-1.bin`의 두 슬롯을 사용한다. `G3SAVE07` 고정 리틀엔디언 형식, 데이터 식별자, 순번, CRC와 임시 파일 후 이름 변경을 적용한다. C 구조체의 포인터나 패딩을 기록하지 않는다. 저장 범위는 다음과 같다.

- 필드 진행, 전투/전투 후 장면 구분, 이벤트 실행 위치와 이미 완료한 이벤트.
- 모든 유닛의 좌표·진영·HP·이동/공격 가능 여부, 현재 행동자·행동 시각·난수 상태.
- 이동 중 경로와 진행도, 공격 동작과 진행 프레임, 피격/보행 포즈, 재생 중인 그래픽 효과.

최근 슬롯이 손상되면 이전 정상 슬롯을 사용한다. 둘 다 손상된 경우 과거 저장을 조용히 되살리지 않는다. 새 슬롯이 전혀 없을 때만 기존 캠페인/대사 저장을 읽는다. 이전 0.6에는 전투 저장 자체가 없었다. 잘못된 전투 상태를 불러오려 해도 현재 상태는 바뀌지 않는다. 음악과 효과음의 PCM 재생 위치는 저장 대상이 아니다.

호스트 검사 75개와 Switch용 AArch64 빌드를 통과했다. ASan/UBSan에서 반복 입력·렌더링·저장 재실행과 변조 상태 복원도 검사했다.

호스트 통합 검사는 원래 배치·HP·능력치를 변경하지 않고 정상 입력으로 플레이해 적 AI를 거쳐 출구 승리까지 진행한다. 중간 저장을 불러온 뒤에도 계속 진행하며, 승리 시 적이 생존해 있어 출구 조건을 검증한다. 별도로 전멸/접촉 이벤트, 필드 3 전체 대사 순서, 공격 명령 시각, 효과 재생 중 저장, 동일 난수 상태로 재실행, 슬롯 손상 복구, 패키지 누락을 검사한다.

## 요청한 단계와 확인 한계

1. 턴/이동/공격 실행 경로를 통합했다. 새 전투의 Switch 실기 실행은 아직 확인하지 못했다.
2. 원본 OBS 공격·피격·효과음·타격 프레임과 해당 난수 소비를 연결했다. 첫 전투에서 쓰지 않는 능동 상태·반격·특수 기술은 지원하지 않는다.
3. 첫 전투 AI 프로필 1을 복원했다. 동률 경로 선택과 우호 유닛 통과는 원본과의 추가 대조가 필요하다. 현재 경로 탐색은 점유된 칸을 모두 막는다.
4. 인트로·승리·패배·접촉 이벤트와 필드 3 연결을 구현하고 정상 배치의 승리 흐름을 검사했다.
5. 전투 중 저장/복원과 난수·이벤트·공격/이동·그래픽 효과 재실행 검사를 완료했다.

이것은 첫 전투의 기능 구현 및 호스트 검증이다. 원본 PC판과의 전체 결과 동일성이나 실기 검증 완료를 뜻하지 않는다. 원본 이동 속도, 모든 그래픽 난수 호출 순서, 효과 혼합 방식, 사망 연출, 오브젝트 깊이 합성, 전투 카메라와 원본 UI의 정확한 재현은 남아 있다. 전체 게임, 이후 전투, 일반 필드 자유 이동, 능력 선택 메뉴, 음성·동영상은 범위 밖이다. 사용자의 기존 음악·이동 확인을 새 전투/SD 저장의 실기 확인으로 확대하지 않는다.
