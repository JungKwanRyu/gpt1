# G3NX 0.6.0 — 수동 턴과 기본 물리 공격 검증

사용자가 이전 버전의 Switch 음악 출력과 캐릭터 이동을 확인했다. 이번 버전은 필드 2 뒤 첫 전투 지도에 **양 진영 수동 조작**의 턴·기본 물리 공격 검증을 연결한다. 적 AI와 BTL 승패 이벤트는 아직 실행하지 않는다. 한 진영의 HP가 모두 0이 되면 검증 종료로 표시하며 후속 스토리로 넘어가지 않는다. 원본과 동일한 첫 전투 완료, 전체 5단계 완료를 의미하지 않는다.

## 설치와 조작

배포 ZIP의 `switch/g3nx` 전체를 복사한다. NRO와 `g3nx.field2`, `g3nx.battle6` 자산을 이전 버전과 섞지 않는다. `Start Game → Shivan Scimitar`에서 대화·필드 2를 진행하고 마지막 안내에서 A를 누른다. 필드 2 저장이 있으면 Load Game으로 재개할 수 있다. 대화·필드 2의 X 저장은 유지하며, 새 턴·공격 검증 상태는 저장하지 않는다.

| 입력 | 턴·공격 검증 화면 |
| --- | --- |
| 방향키 / 스틱 | 목적지 또는 대상 커서; 지도 자동 스크롤 |
| A | 빈 파란 칸이면 이동, 공격 가능한 빨간 대상이면 기본 공격 |
| R | 현재 유닛 대기; 이동·공격을 포기하고 다음 행동자로 진행 |
| L | 현재 행동 유닛의 위치로 커서 이동 |
| X | 초기 배치·HP·턴·난수 상태 초기화 |
| ZL | 이전 이동 검증과 턴·공격 검증 전환; 전환 시 초기화 |
| B / + | 에피소드 선택 / 종료 |

행동 주기가 돌아온 아군과 적 모두 사용자가 조작한다. 적이 선택되면 직접 이동·공격하거나 R로 대기시켜야 한다. 이를 자동 AI로 간주하지 않는다. 한 행동 기회에 이동 1회와 공격 1회이며, 공격 후 이동도 가능하다. 양쪽 행동을 사용하면 다음 유닛으로 자동 진행한다. 이동은 0.5.0처럼 남은 예산을 여러 번 나누어 쓰는 조작과 다르며, 선택한 경로의 비용이 전체 이동 예산 이내인지 검사한 뒤 한 이동 행동을 소비한다.

하단 `TIME`, `TEAM`, `UNIT`, `HP`, `MOVE`, `ATK`로 현재 시각·진영·유닛 번호·HP·남은 행동을 표시한다. `TIME`은 원본의 전역 행동 주기 카운터다. 각 유닛이 행동할 때마다 무조건 1씩 증가하는 턴 번호가 아니다. 공격 결과에는 피해 합계·실제 계산한 타격 수·치명타 수를 표시한다. `RESULT 2`는 일반 적중, `4`는 방어, `5`는 회피다. HP 막대가 감소하고 전투불능 유닛은 지도·점유·턴 선택에서 제외한다.

## 복원 근거와 적용 범위

해당 ALPHA.DLL의 가상 주소 기준으로 정적 분석했다. 원본 Windows EXE/DLL은 실행하지 않았다.

- `10031DE0`, `10030120`, `10035070`: 전역 시각이 행동 주기로 나누어떨어지고 이동/공격 플래그가 남은 유닛을 진영·배열 순서로 선택한다. 비어 있는 시각은 넘긴다. `시각 % 주기 == 1`일 때 행동 플래그를 복구한다. 첫 행동은 시각 8의 마르자나·발라, 시각 9의 살라딘, 11의 무카파, 12의 적 3명, 13의 박쥐 15마리 순이다. 전투 상태·탑승·행동 기회 추가 능력은 지원하지 않는다.
- `10023070..10023409`: `Attack.dat`은 94바이트 디스크 레코드를 108바이트 런타임 레코드로 옮긴다. CHR 오프셋 67의 기본 공격 ID는 살라딘 352, 다른 세 아군 1, 적 297이다. 352는 타격 횟수 2, 나머지는 1이다. 첫 전투의 type 1·고정 사거리·효과 kind 0 자료만 받아들이고 다른 변형은 생성 단계에서 거부한다.
- `10038B20`, `100390B0`, `1008AFB0`, `1008AD80`: 해당 기본 공격의 비용은 `4*(abs(dx)+abs(dy)) + 2*abs(높이 차이)`이며 원본 레코드의 최소 5·최대 8 범위를 적용한다. 같은 높이에서 인접 직선 1칸은 비용 4라 범위 밖이고, 직선 2칸 또는 대각선 1칸은 비용 8이다. 화면의 빨간 대상으로 실제 허용 범위를 확인할 수 있다. 점유 칸을 모두 제외하는 이동 정책은 여전히 검증용 제한이다.
- `1003EB80`, `1003EBE0`, `1003ED60`: 기본 STR·DEX·AC에 초기 사기 80을 반영한다. `stat + trunc((150-morale)*-trunc(stat/2)/150)`을 계산하고 0 미만을 막는다. 첫 전투 기본 공격의 사기 비용은 0이다. 다른 사기 변화·전투 상태는 구현하지 않았다.
- `1003F37A`: `(주무기 power+10)*STR + 주무기 modifier²`에 공격 레코드 보정값의 제곱을 더해 효과 kind 0의 힘을 만든다. 속성 계수를 차례로 곱해 10으로 나누고 AC로 나눈다. AC가 0이면 해당 나눗셈을 생략한다. 다른 효과 kind·특수 능력은 거부한다.
- `10040F20`, `10040E30`, `10041643..10041751`: 수동 검증용 난수 스트림으로 수동 상태가 없는 회피·방어, 기존 정수 피해 변동, 치명타를 계산한다. 회피·방어 능력이 없으면 해당 난수를 소비하지 않는다. 방어 성공 때 무기 방어값을 AC에 더하며 치명타를 적용하지 않는다. 작은 피해의 변동 난수 생략, 양수 적중의 치명타 난수 소비를 유지한다.

**위 연산 검증을 원본 PC판의 전체 전투 결과와 일치한다고 해석하면 안 된다.** 원본은 피격 시각 효과에서도 난수를 소비한다(예: `1003DF8B`). OBS의 실제 공격 효과 생성, 연출·AI를 포함한 전체 난수 호출 순서는 아직 복원하지 않았다. 현재 난수 스트림은 고정 seed 1의 계산 검증용이다. Attack.dat의 타격 수를 직접 순회하며 원본 애니메이션·효과 스케줄러를 대체한다. 반격·상태 효과·장비 부가 효과·죽음 연출·전투 대사·원본 승패 판정·전투 저장은 빠져 있다. 그림은 정지 프레임과 기본 지도 레이어를 계속 사용하며 공격 애니메이션이나 효과음을 추가한 버전은 아니다.

## 검증

호스트 66개 검사 통과. 새 검사에는 사기 보정의 정수 절삭, 주기·진영·배열 순서, 같은 시각의 아군 우선, 행동 플래그 복구, 이동 후 공격/공격 후 이동, 두 타격의 피해·치명타·난수 벡터, 회피·방어 분기, 속성 보정 순서, 잘못된 입력의 상태·난수 보존, 지도 사거리·HP 동기화와 모드 초기화가 포함된다. 같은 생존 유닛의 턴이 연속될 때도 이동 예산과 커서를 갱신하는 회귀 검사를 추가했다. 호스트 렌더링 화면을 확인했다.

공식 SDK로 Switch AArch64 ELF/NRO/NACP 빌드·구조 검사를 수행하고, 런타임 SHA-256과 배포 ZIP CRC를 확인한다. Linux ASan/UBSan으로 입력 반복·렌더링·물리 공격 반복을 검사했다. **새 0.6.0 기능의 Switch 실기, Windows 실행과 원본 PC 결과 대조는 미검증이다.** 기존 음악·이동의 사용자 확인을 새 공격 기능의 검증으로 확대하지 않는다.

재생성·빌드는 루트 README 명령을 따른다. `prepare_battle.py`가 새 헤더와 전투 팩을 생성하므로 호스트/Switch 빌드 전에 실행해야 한다. 다음 구현 대상은 원본 AI 프로필, 피격·반격·공격 연출의 효과 스케줄러와 BTL 승패 이벤트다.
