# 첫 전투 복원 진행

최신 [0.6.0](COMBAT_0_6_0.ko.md)은 첫 전투 지도의 수동 턴·기본 물리 공격·HP·전투불능 검증을 추가한다. 원본 AI·승패 이벤트·전투 상태·공격 연출·전체 난수 호출 순서는 미복원이다. 사용자가 기존 음악과 캐릭터 이동의 Switch 동작을 확인했다. 아래는 0.3.0 당시의 분석 기록이며, 후속 확인 사항은 0.5.0/0.6.0 문서를 따른다.

2026-10-27. 사용자 선택에 따라 원본 규칙을 확인하며 복원한다. 임의의 피해량·턴 순서·AI로 첫 전투를 대체하지 않는다.

**이 변경은 분석 도구와 재사용할 C 모듈을 추가한 것이다. 배포 중인 0.3.0의 플레이 범위는 늘어나지 않았다.** 아직 새 NRO 배포판을 만들지 않았으며, 아래 C 맵·연산 모듈은 게임 실행 흐름에 연결하지 않았다. 요청한 4단계의 첫 전투 완료는 미달성이다.

## 이번에 작성·검증한 부분

- `tools/g3_battle.py`: BTL 전투 배치·이벤트, OBT 맵·타일, CHR 캐릭터 일부 필드 해독. 알 수 없는 값은 이름을 추측하지 않고 보존한다.
- `tools/g3_obs.py`: 기존 이미지 해독에 OBS 동작 테이블 읽기를 추가했다. 원본 프레임 번호·시작 시각·표시 시간을 보존하고 나머지 명령 인자와 꼬리 데이터도 반환한다.
- `homebrew/source/g3_map.c`: 원본 OBT의 기본 레이어를 읽고 RGBA 화면으로 그린다. 데이터 경계와 타일 참조, 출력 버퍼 용량을 검사한다. 객체 레이어 합성·높이·충돌·월드 좌표 투영은 아직 포함하지 않는다.
- `homebrew/source/g3_combat_math.c`: 원본 난수 생성기와 피해량 변동 단계만 분리해 이식했다. 기본 피해량·방어·명중·상태 효과·치명타·행동 순서를 구현했다는 뜻은 아니다.
- `tools/analyze_battle.py`: 원본에서 분석 보고서와 기본 맵 이미지를 다시 만든다. 사용한 개별 파일 및 OBS 리소스의 SHA-256과 해석하지 않은 값을 기록한다.

## 원본에서 확인한 연결과 데이터

챕터 `Chps/0000.CPR`의 필드/전투 호출은 `503(1) → 503(2) → 502(6)` 순서다. 이벤트 조건이 별도로 있으므로 이 목록만으로 전체 챕터 스케줄러가 복원되지는 않는다.

`Flds/0002.FLD`에는 캐릭터 4명의 위치와 동작·이동·대사가 있다. 앞 장면에서 사용한 `703`의 인자를 다음 필드 번호로 일반화하면 잘못된 연결이 된다. 두 필드에 같은 값 2가 존재한다. 0.3.0의 `next_field` 멤버는 그 인자를 보관하는 기존 이름이며, 다음 필드를 실행하는 기능은 없다. 새 연결은 CPR의 호출을 기준으로 구현해야 한다.

`Btls/0006.BTL`은 맵 번호 79와 22개 유닛을 담는다. 아군 캐릭터 ID는 0·1·2·5이며, 적 배치는 ID 501이 15개, ID 505가 3개다. 팀과 초기 좌표를 원본에서 읽으며 전투 능력치를 임의로 부여하지 않는다.

OBT 표본 `Obts/0079.OBT`의 구조:

| 항목 | 확인한 값 |
| --- | --- |
| 블록 수 | 1 |
| 논리 격자 | 45 × 45 |
| 격자별 평면 | 바이트 평면 2개; 이동 비용·충돌 의미는 미확정 |
| 기본 타일 격자 | 45 × 192, 원점 값 (0, -12) |
| 객체 레이어 | 9개; 기본 맵과 별도로 보존 |
| 타일 | 5,762개, 각 40 × 8 픽셀, little-endian RGB555 |
| 기본 비트맵 | 1,800 × 1,536 픽셀 |
| 끝 데이터 | 타일별 바이트 5,762개와 미해석 64바이트 |

기본 레이어의 한 셀은 4바이트이며 뒤의 2바이트가 타일 번호다. 앞의 2바이트를 색상으로 해석하지 않는다. C 렌더러의 카메라 좌표는 기본 비트맵의 픽셀 좌표다. 이를 전투 격자나 원본 월드 좌표와 동일시하지 않는다.

캐릭터 모델 196·352·674·682의 OBS에는 각각 174개 동작 정의가 있다. 동작 3의 이미지 명령은 프레임 3~8을 각각 3시간 단위로 표시하며 전체 길이는 18이다. 시간 단위의 실제 초당 빈도, 방향 선택 및 이미지 외 명령 실행은 별도 확인이 필요하다.

CHR의 디스크 오프셋 58에는 모델 번호가 있고, 77·81의 32비트 값은 런타임 구조의 +0x58·+0x5C로 들어간다. 둘을 HP/MP라고 나란히 가정하지 않는다. +0x5C는 최대 HP 조회 경로에 사용되며, +0x58은 의미를 확정하지 않고 `value_58`로 보존했다. 장비·능력 등에 의한 최대 HP 보정은 아직 구현하지 않았다.

## 전투 연산의 근거와 한계

주소는 해당 원본 `ALPHA.DLL`의 이미지 베이스 0x10000000 기준 가상 주소다. 다른 게임 버전에도 같다고 가정하지 않는다.

| 주소 | 확인한 경로 |
| --- | --- |
| 0x1002C948 이후 | BTL 헤더·배치·이벤트 로더 |
| 0x100C3AB0 이후 | OBT 이미지 생성 경로 |
| 0x1009D7E0 이후 | CHR 로더 |
| 0x100A71D4 이후 | OBS 동작 레코드 로더 |
| 0x10033FC0, 0x10035D60 | 전투 유닛 생성과 CHR 상태 복사/로드 |
| 0x1009EC70 | +0x5C의 기본 HP와 능력 보정을 합산하는 조회 |
| 0x1003DC70, 0x1003DCC4 | 효과 처리에서 0x10041300을 호출하는 경로 |
| 0x10041300~0x1004176E | 피해량/회복량 관련 분기·변동·후처리; 전체 미이식 |
| 0x10041643~0x10041671 | 이번에 옮긴 난수 변동 단계 |
| 0x1003DE0E 이후 | 현재 HP에서 계산값을 빼고 최대 HP 제한 및 사망 처리를 하는 경로 |
| 0x100E75F5~0x100E7616 | 원본 의사난수 생성기 |

난수 상태는 32비트 모듈러 연산으로 `state = state * 214013 + 2531011`을 계산하고 `(state >> 16) & 32767`을 반환한다. 현재 C API는 명시적으로 상태를 받는다. 실제 게임에서는 다른 난수 소비자와 상태·호출 순서를 공유해야 하므로, 이 함수를 단독 검증했다고 전투 결과가 원본과 일치하는 것은 아니다.

해당 변동 단계는 `q = trunc(base / 3)`가 0일 때 값을 유지하고 난수도 소비하지 않는다. 그 외에는 `base + (rand % q) - trunc(base / 6)`을 계산한다. 나눗셈은 0 방향 절삭이며 음수 회복량에도 원본의 부호 있는 나머지 연산을 적용한다. 이 뒤에 상태 배율과 치명타 등의 분기가 이어지므로 이 값을 최종 피해량으로 사용하면 안 된다.

## 검증 결과

호스트 C 빌드는 MSVC `/W4 /WX`로 통과했다. 새 C 모듈 2개는 devkitA64에서도 `-Wall -Wextra -Werror`로 ARM64 객체 컴파일에 성공했다. **최종 NRO 통합·링크 및 실기 구동 검증과는 구분한다.**

기존 검사 19개와 새 검사 11개, 총 30개를 통과했다. 새 검사는 원본 챕터 호출 순서, 첫 전투 유닛·이벤트, OBS 걷기 기록, 잘린 파일과 잘못된 타일 참조, 채널별 알려진 RGB555 값, 잘라낸 영역·화면 밖 처리·출력 버퍼 보호, 원본 난수 고정 수열과 음수/작은 값 연산을 확인한다. 원본 전투의 실제 실행 결과와 대조하는 검사는 아직 없다.

원본 기본 맵을 Python으로 복원한 이미지와 C 렌더러의 여러 뷰포트가 바이트 단위로 일치했다. 객체 레이어까지 포함한 원본 게임 화면과 일치한다는 의미는 아니다.

개별 BTL 파일 455개 중 453개를 끝까지 읽었고, `0018.BTL`과 `0214.BTL`은 레코드가 파일 범위를 넘어 오류로 기록했다. 손상 원인이나 묶음 파일로 대체해야 하는지는 확정하지 않았다. 개별 파일과 묶음의 우선순위도 아직 조사 대상이다.

재현:

```powershell
python tools/analyze_battle.py Store/image.img
.\homebrew\build-host.cmd
python -m unittest discover -s tools -p 'test_*.py'
```

생성 결과는 `reverse/battle-analysis.json`, `reverse/battle6-base-map.png`, `dist/switch/g3nx/battle6-native-base-preview.png`다. 원본·추출 자산·분석 결과는 Git에 포함하지 않는다.

## 남은 순서

1. 0.3.0 실기 확인과 첫 시나리오 저장·입력 회귀 검증.
2. CPR 호출 상태와 필드 2의 캐릭터 동작·동시 이동·카메라를 네이티브 실행기에 연결.
3. OBT 객체·높이·화면 좌표 변환과 원본 경로 탐색·이동 제약 복원.
4. 기본 피해량·방어·명중·치명타·행동 순서·AI·승패 이벤트를 원본 경로로 검증하고 첫 전투를 끝까지 연결.

요청한 기존 4단계 범위를 유지하며, 확인된 모듈을 먼저 쌓은 현재 상태를 4단계 완료로 계산하지 않는다.
