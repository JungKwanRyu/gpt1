# G3NX 0.5.0 — 첫 전투 지도와 지상 이동 검증

후속 확인: 사용자가 Switch에서 음악과 캐릭터 이동을 확인했다. 이후 추가한 턴·공격 검증 기능은 [0.6.0](COMBAT_0_6_0.ko.md)에 기록한다. 아래 미구현 설명과 실기 검증 여부는 0.5.0 작성 시점의 기록이다.

필드 2가 끝난 뒤 A를 누르면 원본 전투 6의 지도와 유닛 배치를 표시한다. 목적지를 직접 선택하고 아군을 이동할 수 있다. **전투를 완료할 수 있는 버전은 아니다.** 일반 필드 자유 이동·턴 진행·공격·적 AI·승패·후속 스토리·음성·효과음은 아직 구현하지 않았다.

ZIP의 `switch/g3nx` 전체를 SD 카드에 복사한다. 기존 파일에 더해 `g3nx.battle6`과 `battle6.obt`가 필요하다. `Start Game → Shivan Scimitar`에서 첫 대화와 필드 2를 진행한 뒤 A로 이동 검증 화면에 들어간다. 필드 2 저장이 있으면 Load Game으로 이어갈 수 있다.

| 입력 | 이동 검증 화면 동작 |
| --- | --- |
| 방향키 / 왼쪽 스틱 | 목적지 커서, 화면 자동 스크롤 |
| A | 파란 범위 안의 목적지로 이동하고 비용 차감 |
| L / R | 아군 네 명 중 선택; 각자의 남은 예산 유지 |
| X | 전체 배치와 이동 예산 초기화 |
| B / + | 에피소드 선택 / 종료 |

이 화면의 X는 저장이 아니다. 대화·필드 2에서의 X 저장과 기존 저장 파일 형식은 유지한다. 이동 검증 상태는 저장하지 않으며 재진입하면 원본 배치로 돌아간다. 아군은 초록, 적은 빨강, 이동 범위는 파랑, 커서는 노랑으로 표시한다. 하단 `P1 MP24/24`는 선택한 아군과 남은/최초 이동 예산이다. 전투 BGM 연결을 확인하지 않았으므로 검증 화면에서는 필드 BGM을 멈춘다.

## 원본 근거

해당 `ALPHA.DLL`의 가상 주소 기준이다. 원본 Windows 바이너리는 실행하지 않았다.

- `10033FC0`, `10099EA0`, `10032900`, `100329A0`: 격자 중심의 월드 좌표는 `(40*x+20, 40*y+20, 20*높이)`다. 기본 비트맵 좌표는 `sx=40*x+20-40*원점x`, `sy=32*y+16-12*높이-8*원점y`다. 첫 지도 원점은 `(0,-12)`다.
- `1008A680`, `1008A880`: 첫 지도에서 첫 바이트 평면은 높이, 둘째는 통행 속성이다. 작은 지상 유닛은 목적지 속성 bit 0이 있거나 높이 차이가 2를 초과하면 통과할 수 없다. 첫 전투의 22개 CHR은 모두 작은 지상 유닛이다. 박쥐도 외형으로 비행 판정을 바꾸지 않는다.
- `1008A920`: 인접 이동 비용은 `4*(abs(dx)+abs(dy)) + 2*abs(높이 차이)`다. 대각선 이동도 합산하며 별도의 코너 통과 금지를 추측해 추가하지 않았다. 비행의 고도 조회는 미복원이므로 현재 API가 비행 경로를 요청받으면 지원하지 않는 값으로 거부한다.
- `1009D7E0`, `1009E300`, `1009EC70..1009EED0`: CHR의 장비·능력과 Job/Abi/Item DAT를 읽는다. 직업의 능력 상한과 장비의 기본 능력치 보정을 적용한다. CHR 10바이트 능력치의 마지막 두 값은 **행동 주기, RANGE 순서**다. 행동 주기를 실제 턴 실행기에 연결한 것은 아니다.

| 아군 | 초기 최대 HP | 이동 예산 | 행동 주기 원본 값 |
| --- | ---: | ---: | ---: |
| 살라딘 | 1000 | 24 | 9 |
| 마르자나 | 500 | 24 | 8 |
| 무카파 | 1300 | 16 | 11 |
| 발라 | 580 | 29 | 8 |

CHR 기본 HP만 사용하면 살라딘은 700, 무카파는 1000이지만 능력·직업 보정 후 값은 위와 같다. 이동 예산 24는 평지 직선 6칸에 해당한다. 기본 능력치 계산은 초기 상태용이며 사기·전투 상태·탑승 연계의 모든 보정을 포함하지 않는다.

경로 탐색은 비용 제한 Dijkstra를 사용한다. **유닛이 있는 칸은 아군·적군 모두 통과하지 못하게 제한한 검증용 정책**이다. 원본의 진영별 통과 정책과 경로 비용이 같은 경우의 우선순위는 아직 복원하지 않았다. 원본의 이동 가능 범위 전체와 동일하다고 주장하지 않는다. 목적지에 즉시 좌표를 적용하며 보행 애니메이션·방향 변화는 미구현이다. OBS 0번 동작의 첫 이미지와 원본 기준점만 표시한다. 지도 객체의 깊이 합성·가림도 미구현이며 기본 레이어만 그린다.

지도 파일은 생성 시 고정한 크기와 CRC를 검사하고, 스프라이트 팩 식별자·이미지 범위를 검사한다. 배포 보고서에는 모든 런타임 파일의 SHA-256을 남긴다. 원본 데이터와 생성 헤더·팩·지도는 Git에 넣지 않는다.

## 재생성과 검증

저장소 루트에서 기존 0.4.0 준비 절차에 다음을 **호스트/Switch 빌드 전** 추가한다.

```sh
python tools/prepare_battle.py Store/image.img --font /path/to/Korean.ttf
```

최신 필드 2 종료 안내를 생성하기 위해 `prepare_story.py --field 2`도 다시 실행한다. 전체 명령은 루트 README를 따른다. `g3_battle6_data.h`를 임의로 작성하거나 이전 헤더로 대체하지 않는다.

호스트 검사 53개 통과: 기존 대화·필드·저장·오디오 검사와 함께 높이 투영, 높이 차이 제한, 통행 속성, 대각선 비용, 경로 우회·예산·점유 제한, 캐릭터별 예산 유지·배치 초기화, 손상 지도 거부, 렌더링 버퍼 경계, 실제 CHR/DAT 초기 능력치와 새 패키지 누락·변조 거부를 검사했다. 호스트 렌더링 이미지도 확인했다. Linux 공식 SDK로 AArch64 ELF/NRO/NACP 빌드·구조 검사를 통과했다. ZIP의 파일 해시와 압축 CRC를 검사했다. Windows 빌드와 Switch 실기 실행은 이번 환경에서 검증하지 않았다.

다음 구현 대상은 원본 행동 플래그·행동 주기를 사용하는 턴 처리, 명중·방어·피해·상태 처리, AI 프로필과 전투 이벤트의 승패 조건이다. 이들이 연결되어야 첫 전투 완료로 판단한다. 현재 요청한 5단계 전체 완료 상태는 아니다.
