# G3NX 0.3.0 — 첫 시나리오 실행기

사용자가 0.2.0의 스위치 실기 동작을 확인했다. 이를 기준으로 시나리오 실행과 진행 저장을 추가했다. **전체 게임 이식이 완료된 상태는 아니다. 현재 실제로 실행하는 범위는 시반슈미터의 첫 대화 필드 1이다.**

## 설치와 확인 순서

`dist/g3nx-scenario-0.3.0.zip` 안의 `switch` 폴더를 SD 카드 최상위에 복사하고 이전 파일을 덮어쓴다. 다음 세 파일이 함께 있어야 한다.

```text
switch/g3nx/g3nx.nro
switch/g3nx/g3nx.title
switch/g3nx/g3nx.story
```

1. hbmenu에서 실행하고 Start Game → Shivan Scimitar를 선택한다.
2. 발라와 살라딘의 첫 대화가 나온다. A로 대사 페이지를 넘긴다.
3. X로 현재 진행을 저장한다. 왼쪽 검은 여백의 `SAVED` 또는 `SAVE FAILED` 표기를 확인한다.
4. B로 에피소드 선택에 돌아간 뒤 다시 B로 타이틀에 돌아간다. Load Game으로 저장한 대사 페이지가 복원되는지 확인한다.
5. 첫 장면의 대사가 끝나면 다음 필드가 아직 미지원이라는 안내가 나온다. 여기서 임의 전투나 가짜 완료 상태로 넘어가지 않는다.

저장 파일은 `g3nx-progress-0.bin`과 `g3nx-progress-1.bin`이다. 원래 PC 게임의 저장 파일과 다른 G3NX 전용 형식이다. 두 슬롯을 번갈아 기록하고 CRC가 유효한 최신 슬롯을 읽는다. 최신 파일이 손상되면 유효한 이전 슬롯으로 돌아간다. 최초 저장이나 양쪽 슬롯 모두 손상된 경우에는 복원할 수 없다. 버전/시나리오 식별자가 다르면 읽지 않는다.

## 새로 구현한 동작

- 원본 FLD 조건과 명령을 실행하는 C 시나리오 실행기.
- 배경 전환, 좌우/중앙 인물 그림, 한글 대사 페이지, 상태 플래그와 조건 비교, 대기와 종료 경계.
- 첫 필드가 참조하는 대사 명령 51개를 원본 순서대로 진행한다. 길이가 긴 대사는 여러 페이지로 나눈다.
- 인물 그림은 OBS의 여러 타일을 모두 조합해 사용한다. 실행 중 C 알파 합성기로 배경, 인물, 대사 레이어를 조합한다.
- 별도 진행 저장 및 Load Game 연결. 저장/로드 상태에는 명령 위치, 활성 이벤트, 플래그, 인물·배경, 대사 페이지와 대기값을 포함한다.

대사의 텍스트는 원본 FLG에서 읽는다. `/m0.../m1`, `/n`을 이름과 줄바꿈으로 해석하고, 텍스트 타이밍·색상 태그는 프런트엔드 표시 규칙에 맞게 단순화한다. 폰트 파일 자체는 배포하지 않고 한글 텍스트 레이어를 제작 시 래스터화한다. 인물과 대사 창 배치는 원본 UI를 완전히 재현한 것이 아니라 새 프런트엔드 규칙이다.

## 리버싱 근거와 남은 범위

EPS 로더 `0x100A7DD0`는 세 에피소드 목록의 34바이트 레코드를 읽고 이름 20바이트를 반전한다. 실제 파일에서 20/17/20개 레코드를 읽었다. 끝의 두 바이트는 의미를 확정하지 않고 그대로 기록한다.

CPR 로더 `0x100ADFF0`와 필드 로더 `0x100C78D0`에서 구조를 확인했다. 필드는 12바이트 헤더, 12바이트 단위 배우 레코드, 이벤트 목록으로 구성된다. 각 이벤트에는 종류, 조건 배열과 명령 배열이 있고, 배열 항목은 14바이트(16비트 값 7개)다.

시작 챕터 0/20/37의 초기 명령 `503`은 각각 필드 1/83/68을 요청한다. 시반슈미터의 필드 1에는 원본 인덱스 묶음과 개별 파일이 같은 내용임을 확인했다. 실행기에 넣은 명령과 조건은 이 자료에서 생성한다.

조건 100은 `0x100BD080`에서 플래그를 비교하며, 비교 함수는 `0x100BCFA0`다. 지원 대상인 조건식과 명령의 근거는 생성된 디스어셈블 및 `reverse/scenario-analysis.json`에 보존했다. 해독되지 않은 명령/조건에 도달하면 실행기를 오류 상태로 전환하며, 이를 정상 진행으로 간주하지 않는다.

**미구현:** 나머지 에피소드의 이벤트 실행, 필드 2 이후의 캐릭터 이동·맵 동작, 원본 전투/AI/능력치·아이템 처리, 전체 스토리 연결, 튜토리얼, PC 세이브 호환, 음악·음성·효과음, 동영상. 첫 장면의 팔레트 페이드와 원본 텍스트 표시 타이밍도 아직 재현하지 않는다. BGM 명령은 트랙 값을 보존하지만 소리를 재생하지 않는다.

다음 복원 대상은 필드 2의 배우 배치와 이동 명령, OBS 동작/애니메이션 테이블, OBT 맵 형식이다. 나머지 두 에피소드의 첫 필드도 같은 이동 계통 명령에 의존하므로 이 부분이 복원되어야 진행 범위를 넓힐 수 있다.

## 검증과 재생성

```powershell
python tools/prepare_story.py Store/image.img
python tools/prepare_title.py Store/image.img
python tools/build_switch.py
.\homebrew\build-host.cmd
python tools/test_story.py
python tools/test_title.py
python tools/test_resources.py
python tools/package_release.py
```

시나리오 검사에는 원본 EPS/CPR/FLD 구조, 잘린 입력 거부, 첫 필드의 대사 51개 순서와 플래그/필드 2 경계, 저장 복원, 최신 슬롯 손상 시 이전 슬롯 복구, 유효 CRC를 붙인 잘못된 상태 거부가 포함된다. 실제 C 실행기와 합성기를 PC에서도 호출한다. `story-native-preview.png`는 같은 C 코드를 사용한 PC 출력이며 실기 캡처가 아니다.

이 버전의 NRO는 devkitA64/libnx로 컴파일하고 NRO/NACP 구조를 검사했다. 0.3.0의 실기 실행, 대사 넘김, SD 카드 저장과 불러오기는 아직 확인하지 않았다. 0.2.0의 실기 성공이 새 기능의 실기 검증을 대신하지 않는다.
